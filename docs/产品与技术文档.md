## 1. 项目概述

### 1.1 一句话定位

**本地零工平台**是一款面向「本地兼职 / 零工撮合」场景的移动端产品：**雇主发布岗位，打工人找活、报名、上岗、互评**，覆盖从「发活」到「结评」的完整闭环。

### 1.2 项目背景

- 本项目是**教学级 / 练手级**项目：以黑马程序员「黑马点评」课程的经典后端架构为骨架，替换成自己的业务（零工撮合），目标是做一个**经典、全面、规范**的 Spring Boot 项目。
- 核心诉求是**练技术**：把缓存穿透/击穿/雪崩、Redis GEO、分布式锁、雪花 ID、RabbitMQ、Feed 推流、Bitmap 签到等经典面试知识点，落到一个真实业务里跑通。
- **不追求 QPS / 压测 / 性能指标**——重点在「写规范、学技术」，而非「扛流量」。

### 1.3 目标用户与角色

| 角色 | 说明 | 核心诉求 |
|---|---|---|
| **打工人**（role=0） | 找零活干的人 | 找附近的活 → 报名 → 被录用 → 上岗 → 评价雇主 |
| **雇主**（role=1） | 发布零活的人 | 发岗位 → 审核报名 → 录用 → 完成 → 评价工人 |

> 一个账号**可兼任两种角色**（`tb_user.role` 字段标记当前身份），登录后可切换。

### 1.4 核心用户旅程

```
【打工人侧】登录 → 逛分类/搜附近岗位 → 报名(秒杀名额) → 等雇主录用 → 上岗 → 评价雇主
【雇主侧】  登录 → 发布岗位(含经纬度/名额/薪资) → 审核报名 → 录用/拒绝 → 完成 → 评价工人
【社交侧】  关注感兴趣的雇主 → 刷关注动态 Feed → 点赞 / 发布自己的晒单动态 → 每日签到
```

## 5. 核心技术实现

> 本节是项目的「技术含金量」所在，按知识点逐个拆解。

### 5.1 登录认证（双拦截器 + ThreadLocal）

- **发验证码**：`POST /user/code` 生成 6 位随机码存 Redis（`login:code:{phone}`，TTL 2min），日志打印模拟短信。
- **登录**：`POST /user/login` 校验验证码 → 生成 token(UUID) 存 Redis Hash（`login:token:{token}` 存 UserDTO，TTL 30min），**首次登录自动注册**。
- **双拦截器**：
  - `RefreshTokenInterceptor`：放行所有请求，有 token 就刷新有效期 + 把用户放进 ThreadLocal。
  - `LoginInterceptor`：校验 ThreadLocal 是否有用户，无则 401。
- **`UserHolder`**：ThreadLocal 保存当前用户，请求结束 `remove()` 防内存泄漏。
- **鉴权策略**：浏览类接口（岗位列表/详情/分类/评价）匿名放行，写操作需登录。

### 5.2 缓存三问题（核心）

针对岗位详情的高并发读，统一封装在 `CacheClient`：

| 问题 | 方案 | 实现 |
|---|---|---|
| **穿透**（查不存在的数据） | 空对象缓存 + 布隆过滤器 | 空结果存 `cache:job:null:` TTL 2min；`JobBloomFilter` 启动预载岗位 id，查库前先判布隆 |
| **击穿**（热点 key 过期瞬间） | 互斥锁 / 逻辑过期 | `queryWithMutex` 用 Redisson RLock 互斥重建；`queryWithLogicalExpire` 用逻辑过期+异步重建(线程池) |
| **雪崩**（大量 key 同时过期） | TTL 加随机值 | `set` 时给 TTL 加随机扰动 |

- **缓存一致性**：改/下架岗位后主动删缓存。
- **布隆过滤器**：Redisson `RBloomFilter`，初始化失败降级（直接查库）。

### 5.3 附近搜索（Redis GEO）

- 岗位发布时把 `(经度, 纬度, jobId)` 写入 `geo:job:{categoryId}`。
- 查询用 **`GEOSEARCH`** 按「经纬度 + 半径」搜索，`WITHDIST` 返回距离，按距离升序分页。
- 拿到的岗位 id 列表回 DB 取完整详情。
- **演示模式**：种子数据集中在北京市区，前端「只看附近」固定以北京市中心 (116.4074, 39.9042) 为圆心、半径 20km，保证任何位置打开都能看到岗位（真实项目改回 `navigator.geolocation`）。

### 5.4 报名秒杀（Lua 原子 + 雪花 ID + 一人一单）

报名是核心链路，所有报名统一走秒杀逻辑：

1. **生成单号**：`RedisIdWorker` 雪花算法（1 符号位 + 31 时间戳 + 32 序列号），序列号用 Redis `INCR` 按天自增，解决多机 workerId 冲突。
2. **执行 Lua**（`seckill.lua`，Redis 内原子执行）：查名额 → 查一人一单 → 扣名额 → 记标记，返回 0/1/2。
3. **发 MQ**：成功后生产者发消息到 RabbitMQ。
4. **消费者落单**：`@RabbitListener` 幂等校验 → 写 `tb_job_application` → 扣 DB 名额 → 手动 ACK；失败 `basicNack` 进死信队列。

> **为什么用 Lua**：查名额+扣名额+判重必须原子，否则并发下会超卖 / 重复报名。用 Redis 脚本把多步操作打包成一次原子执行。

### 5.5 RabbitMQ 异步落单（confirm + 手动 ACK + 死信）

- **为何用 MQ**：报名先扣 Redis 名额、快速返回，DB 落单异步做，削峰 + 解耦 + 提高响应速度。
- **可靠性三件套**：
  1. **发布确认 confirm**：`publisher-confirm-type: correlated` + confirm 回调，投递失败记日志告警。
  2. **不可达路由退回 return**：`publisher-returns: true` + return 回调，路由 key 写错时 `NO_ROUTE` 告警（不再静默丢消息）。
  3. **手动 ACK + 死信**：消费者落单成功才 ACK，失败重试超限进死信队列 `job.application.dlq`。
- **与黑马点评差异**：本项目用 **RabbitMQ 替代 Redis Stream**（这是有意为之的选型差异）。

### 5.6 分布式锁（自研 → Redisson 演进线）

- **教学版 `SimpleRedisLock`**：`SET NX EX` 加锁 + Lua 脚本原子释放（判断线程标识，避免误删别人的锁）。
- **生产版 `Redisson RLock`**：可重入 + watchdog 自动续期，接入两处：
  1. `CacheClient.queryWithMutex` 缓存击穿互斥锁（替换自研 setnx 锁）。
  2. `audit` 审核加业务锁（对标黑马「一人一单」，防并发重复审核，锁粒度 = 单条报名记录）。

### 5.7 Feed 推流（ZSet 收件箱 + 滚动分页）

- **收件箱模型**：每个用户的关注流存 `feed:{userId}`（ZSet，member=动态 id，score=时间戳）。
- **发布推流**：发布动态 → 读粉丝集合 → 推送到所有粉丝收件箱（+ 推给自己，保证自己的动态也出现在动态页顶部）。
- **关注滚入**：关注某人时，把对方最近 3 条历史动态滚入自己收件箱。
- **滚动分页**：`ScrollResult`（lastId + offset）用 `ZREVRANGEBYSCORE` 从高到低翻页，避免 offset 分页在大 offset 下性能退化。

### 5.8 签到（Bitmap）

- `sign:{userId}:{yyyyMM}` Bitmap，`SETBIT` 记当月第几天。
- `BITFIELD GET` 取本月签到位，从最低位往前数连续 `1` 得连续签到天数。

### 5.9 统一规范

- 统一返回体 `Result<T>`（code/msg/data/total）。
- 全局异常 `WebExceptionAdvice`（含参数校验异常处理）。
- 参数校验 `Validation`。
- 敏感配置（数据库密码等）用占位符，注释提示生产用环境变量。

## 7. 部署与启动

- Docker（MySQL / Redis / RabbitMQ）

### 7.2 启动步骤

```bash
# 1. 启动三中间件（项目根目录）
docker compose up -d

# 2. 建表 + 种子数据（首次）
#    执行 backend/src/main/resources/db.sql（分类种子数据已内置）

# 3. 启动后端
cd backend && mvn spring-boot:run
#    后端跑在 8080，接口文档 http://localhost:8080/doc.html

# 4. 构建前端
cd frontend && npm install && npm run build
#    产物 frontend/dist

# 5. 启动 nginx（root 指向 frontend/dist，监听 8088）
#    浏览器访问 http://localhost:8088
```

### 7.3 常见问题

| 问题 | 原因 / 解决 |
|---|---|
| `docker ps` 看不到 nginx | nginx 是本机进程，不是容器（见 3.3） |
| 改后端代码不生效 | 需重启 `mvn spring-boot:run` |
| 改前端代码不生效 | 需 `npm run build` 重建 dist，浏览器 Ctrl+F5 硬刷新 |
| 岗位详情报「不存在」 | 布隆过滤器启动时预载，造完数据需重启后端 |
| MySQL 连 3307 | 本机原生 MySQL 占 3306，Docker 映射到 3307 |

## 8. 与黑马点评的关系

本项目**骨架对齐黑马点评**（hm-dianping），但有意的差异：

| 维度 | 黑马点评 | 本项目(linggong) |
|---|---|---|
| 业务 | 店铺点评/优惠券秒杀 | 零工撮合(岗位/报名/互评) |
| 消息队列 | Redis Stream | **RabbitMQ**(confirm + 手动 ACK + 死信) |
| 登录 | 验证码登录 | 同(验证码登录，无密码，无 PasswordEncoder) |
| 缓存 | CacheClient 三方法 | 同(穿透/击穿/雪崩 + 布隆 + 逻辑过期) |
| 分布式锁 | SimpleRedisLock + Redisson | 同(自研演进到 RLock) |
| 前端 | 黑马自带的 H5 | 自己写(Vue3 + Vite + Vant4) |

> 保留对齐的部分：CacheClient 三方法拆分、SimpleRedisLock 用 `unlock.lua` 原子释放、UserHolder 普通 ThreadLocal、登录存 Redis Hash。
